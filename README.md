# TRACE-SR

Course project on learning API recommendation from explanations of a small language model's mistakes. The project compares label-only fine-tuning, correct-answer explanations, and error explanations generated by either the student or GPT.

The student is `meta-llama/Llama-3.2-3B-Instruct`, fine-tuned with LoRA. We train and evaluate each condition separately on each dataset.

## Experiments

Every condition includes the main task, request to the correct API set. Conditions B-E also include an explanation task on the same subset of training samples whose frozen student draft contains an error.

| Condition | Explanation source | Auxiliary task |
| --- | --- | --- |
| A | None | Labels only |
| B | GPT | Request to correct-answer explanation and APIs |
| C | Student | Request to correct-answer explanation and APIs |
| D | GPT | Request and draft to error explanation and corrected APIs |
| E | Student | Request and draft to error explanation and corrected APIs |

## Repository layout

```text
data/          Prepared train/dev/test splits and API descriptions
outputs/       Frozen student drafts and student/GPT training explanations
generate/      Scripts for producing drafts and explanations
tools/         Shared data loading, API mapping, evaluation, and mapping tests
train/         LoRA fine-tuning and dev/test prediction
TRACE_SR.pdf   Project proposal
```

Prepared data and explanations are included so the five training conditions can use the same inputs. Upstream archives and per-example predictions are stored locally.

The local preprocessing archive referenced by the data documentation is not included in Git.

## Setup

Run the commands from this directory in a Python environment with a CUDA GPU available for model generation and training:

```bash
python -m pip install -r train/requirements.txt
```

Obtain access to the Llama 3.2 model on Hugging Face and authenticate before downloading it, or pass `--model /path/to/Llama-3.2-3B-Instruct` to use an existing local copy.

## Train and evaluate

```bash
# Train the label-only baseline; evaluate dev after each epoch.
python train/sft.py --dataset programmableweb --condition A

# Train with GPT error explanations.
python train/sft.py --dataset programmableweb --condition D

# Evaluate the checkpoint selected using dev F1.
python train/predict.py --dataset programmableweb --condition D --split test

# Evaluate the original student without an adapter.
python train/predict.py --dataset programmableweb --split test

# Evaluate the auxiliary tasks.
python train/evaluate_aux.py --batch-size 96
```

Dataset arguments are `programmableweb`, `apibench_java`, and `apibench_python`; conditions are `A`, `B`, `C`, `D`, and `E`. Checkpoints are written to `checkpoints/` and predictions and metrics to `results/`. See [train/README.md](train/README.md) for training settings, explanation truncation, and output files.

## Regenerate supervision

The prepared files in `outputs/` can be used directly for training. To regenerate them, follow [generate/README.md](generate/README.md). Student generation uses the local model; GPT generation additionally requires an `OPENAI_API_KEY` environment variable.

## Mapping and evaluation checks

```bash
python -m unittest discover -s tools/tests
python tools/evaluate.py --dataset programmableweb
```

API mapping uses the catalog without consulting the gold set. Evaluation reports precision, recall, micro F1, macro F1, and exact-set accuracy. See [tools/README.md](tools/README.md) for alias and signature handling.
